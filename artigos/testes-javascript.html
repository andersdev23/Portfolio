Testes em JavaScript: comece pela regra de negócio

Uma tela pode parecer correta enquanto a regra por trás dela está errada. Testar uma função pequena é uma forma prática de começar a verificar o comportamento do sistema sem depender de cliques no navegador.

Antes do teste, defina o comportamento

Considere um exemplo didático: uma função recebe o estoque disponível e a quantidade solicitada, e devolve o saldo depois da reserva. O objetivo aqui é testar uma regra isolada; não representar a implementação de um sistema de logística completo.

Antes de escrever código, descreva o contrato: estoque e quantidade devem ser números inteiros, o estoque não pode ser negativo, a quantidade precisa ser positiva e a reserva não pode superar o saldo. Com essas decisões explícitas, os testes passam a responder perguntas concretas.

Por exemplo: reservar três unidades de um estoque de dez deve retornar sete. Reservar todas deve retornar zero. Pedir mais do que existe deve gerar um erro, em vez de produzir um saldo negativo.

Isole a regra da interface

Crie o arquivo estoque.mjs. A função não precisa conhecer formulários, banco de dados ou mensagens da interface. Ela recebe valores e devolve um resultado, ou informa que a operação é inválida.

JavaScript · estoque.mjs
export function reservar(estoque, quantidade) {
  if (!Number.isInteger(estoque) || estoque < 0) {
    throw new TypeError('Estoque inválido');
  }

  if (!Number.isInteger(quantidade) || quantidade <= 0) {
    throw new TypeError('Quantidade inválida');
  }

  if (quantidade > estoque) {
    throw new RangeError('Estoque insuficiente');
  }

  return estoque - quantidade;
}

Essa separação permite mudar a apresentação sem reescrever a regra. Também evita que cada teste precise montar uma página inteira só para verificar uma subtração com restrições.

Teste o caminho esperado e os limites

Em um Node.js com suporte ao test runner nativo, crie estoque.test.mjs ao lado da função. O módulo node:test organiza os cenários; node:assert/strict compara resultados e verifica exceções.

JavaScript · estoque.test.mjs
import test from 'node:test';
import assert from 'node:assert/strict';
import { reservar } from './estoque.mjs';

test('desconta a quantidade reservada', () => {
  assert.equal(reservar(10, 3), 7);
});

test('permite reservar todo o saldo', () => {
  assert.equal(reservar(3, 3), 0);
});

test('rejeita uma reserva acima do saldo', () => {
  assert.throws(() => reservar(2, 3), RangeError);
});

test('rejeita quantidade igual a zero', () => {
  assert.throws(() => reservar(10, 0), TypeError);
});

test('rejeita estoque negativo', () => {
  assert.throws(() => reservar(-1, 1), TypeError);
});

Execute o comando abaixo na pasta dos dois arquivos. Não é necessário instalar uma biblioteca de testes para este exemplo.

Terminal
node --test estoque.test.mjs

Use os testes para revelar decisões que faltam

Depois dos primeiros cenários, pergunte o que ainda não foi decidido. Quantidades fracionadas seriam permitidas em outro domínio? O formulário entrega números ou textos? A resposta deve orientar o contrato da função e a conversão de dados na entrada da aplicação.

Experimente acrescentar casos para números fracionados e valores como "3". Nesta implementação, ambos devem ser rejeitados. Depois altere a regra de propósito e veja se o teste correspondente falha: isso ajuda a conferir se a verificação realmente protege o comportamento descrito.

Uma suíte verde confirma apenas os cenários exercitados. Integrações, persistência e concorrência exigem outras verificações. O primeiro passo útil é ter testes pequenos, com nomes que expliquem a intenção e falhas que apontem uma regra específica.

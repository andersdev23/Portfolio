Um menu acessível começa pelo teclado

Se a navegação depende de acertar um ícone com o mouse, parte da experiência ficou de fora. Um teste com teclado revela rapidamente se os controles podem ser encontrados, acionados e compreendidos.

Use o elemento que já sabe ser um botão

Para abrir ou fechar uma região da página, comece com <button type="button">. Ele já participa da navegação por teclado e responde à ativação nativa. Um div com um evento de clique exigiria recriar parte desse comportamento.

Uma navegação de site comum pode ser tratada como uma região expansível. Ela não precisa receber o papel ARIA de menu de aplicativo, que traz outras expectativas de interação. Links continuam sendo links, e o botão controla a visibilidade deles.

No exemplo, o botão começa oculto e os links começam disponíveis. Assim, sem JavaScript, a navegação continua utilizável. O script apresenta o controle e passa a administrar o estado expandido.

HTML
<button id="abrir-navegacao" type="button"
  aria-expanded="false" aria-controls="navegacao" hidden>
  Navegação
</button>

<nav id="navegacao" aria-label="Principal">
  <a href="index.html">Início</a>
  <a href="blog.html">Blog</a>
</nav>

Mantenha visibilidade e estado de acordo

O atributo aria-expanded informa se o conteúdo controlado está aberto. O atributo hidden oculta a região quando ela não deve estar disponível. Atualize os dois na mesma função para evitar uma interface visível que seja anunciada como fechada, ou o contrário.

JavaScript · executar após o HTML
const botao = document.getElementById('abrir-navegacao');
const navegacao = document.getElementById('navegacao');

function definirAberto(aberto) {
  botao.setAttribute('aria-expanded', String(aberto));
  navegacao.hidden = !aberto;
}

botao.hidden = false;
definirAberto(false);

botao.addEventListener('click', () => {
  const aberto = botao.getAttribute('aria-expanded') === 'true';
  definirAberto(!aberto);
});

document.addEventListener('keydown', (evento) => {
  const focoNaNavegacao = navegacao.contains(document.activeElement);
  const focoNoBotao = document.activeElement === botao;

  if (evento.key === 'Escape' && !navegacao.hidden &&
      (focoNaNavegacao || focoNoBotao)) {
    definirAberto(false);
    botao.focus();
  }
});

Enter e Espaço acionam o botão por seu comportamento nativo. O tratamento adicional de Escape fecha a região quando o foco está nela ou no próprio controle e devolve o foco ao botão. Como essa navegação não é modal, a pessoa pode seguir usando Tab para sair dela.

Deixe claro onde o foco está

O foco precisa se destacar do fundo. Remover o contorno sem oferecer outro indicador faz a navegação parecer perdida. Uma regra simples pode usar a cor de destaque do próprio site:

CSS
button:focus-visible,
a:focus-visible {
  outline: 2px solid #c1ed78;
  outline-offset: 5px;
}

button {
  min-height: 44px;
  padding: 10px 16px;
}

[hidden] {
  display: none !important;
}

O seletor de hidden evita que outra regra visual, como display: flex, faça o conteúdo fechado reaparecer. O tamanho do controle também facilita o toque em telas pequenas.

Faça uma volta completa sem o mouse

  1. Use Tab até chegar ao botão e confira se o foco está visível.
  2. Abra com Enter; repita usando Espaço.
  3. Avance pelos links com Tab e volte com Shift + Tab.
  4. Pressione Escape dentro da navegação: ela deve fechar e o foco deve voltar ao botão.
  5. Confirme que os links ocultos deixam de participar da sequência de Tab.
  6. Desative o JavaScript e confirme que os links iniciais continuam disponíveis.

Esse roteiro não substitui uma avaliação completa de acessibilidade. Ele cobre um conjunto pequeno e verificável de comportamentos que costuma ser esquecido quando a revisão se limita ao visual.
